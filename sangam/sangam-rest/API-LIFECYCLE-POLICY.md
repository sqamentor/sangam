# Sangam REST API lifecycle policy (SL-38, SL-46)

## 1. Versioning

- The contract is `sangam-rest/api/sangam-api.yaml`, generated by `api/gen_openapi.py`. The base path is `/api/v1`.
- Within `/api/v1` only compatible changes are made: new paths, new operations, new optional parameters, new
  response properties, new enum values in responses (clients must accept unknown values and unknown problem codes).
- A breaking change goes to a new base path (`/api/v2`). `/api/v1` then follows section 2 as a whole.

## 2. Deprecation and sunset

- Every deprecation is an entry in `api/sangam-api-deprecations.yaml`: method, path, `deprecated` date, `sunset`
  date, changelog `link`, optional `successor`.
- **Minimum support window: 365 days** between `deprecated` and `sunset`. The registry may raise it
  (`policy.minimumSupportDays`) but not lower it; the server refuses to start with a shorter entry
  (`ApiDeprecationRegistry`).
- The generator marks the operation `deprecated: true` with `x-sangam-deprecated-on`, `x-sangam-sunset` and
  `x-sangam-successor`.
- From the deprecation date the server adds to each response of that operation:
  - `Deprecation: @<unix seconds>` (RFC 9745);
  - `Sunset: <HTTP-date>` (RFC 8594);
  - `Link: <changelog>; rel="deprecation"` and, when set, `Link: <successor>; rel="successor-version"` (RFC 5829).
- From the sunset date (00:00 UTC) the operation answers `410` with problem code `API_SUNSET`, and the request does
  not reach the controller or claim an idempotency key (`DeprecationHeadersFilter`, filter order 90, before
  idempotency at 100).
- The operation may be deleted from the generator only after the sunset date.

## 3. Compatibility gate

`OpenApiCompatibilityTest` compares the generated spec with the last released spec in `api/baseline/` (now
`sangam-api-0.1.0.yaml`, the contract as of commit 15e4135). The build fails on:
- a removed path or operation that is not past its sunset in the registry;
- a removed parameter, a new required parameter, an optional parameter or request body made required;
- a removed success response or response media type;
- a changed type or format, request enum values removed, request `min*`/`max*` tightened, new required request
  properties, a removed property, a response property no longer required.

At each release the released `sangam-api.yaml` is copied to `api/baseline/sangam-api-<version>.yaml` and the test
points at it.

## 4. Changelog

- Each deprecation entry links to its changelog section. The changelog states what is deprecated, the sunset date,
  the successor and a migration example.
- Release notes list every registry entry added and every operation removed at sunset in that release.
