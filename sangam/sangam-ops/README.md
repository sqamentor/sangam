# sangam-ops

Operations back ends. Independent implementations from public behaviour and the published Camunda 7 / Operaton table names.

**Evidence level:** compiled, with `OpsTest` run on H2, using hand-made tables that hold only the columns these classes read. Not run against real `ACT_*` schemas or a Tier-1 database.

The creator snapshot is bound to `TenantContext` for the row so the registry's visibility, privacy and consent ports evaluate the creator. Test `RegistryPartyBulkSinkH2Test`. **Gap:** no UI |

## Integration notes

- **Tables:** the `OpsSchema` tables (`OPS_MIG_CHECKPOINT`, `OPS_MIG_ROW`, `OPS_USAGE_DAILY`, `OPS_SEARCH_DOC`, `OPS_SEARCH_ALIAS`, `OPS_INDEX_JOB`, `OPS_VARIABLE`, `OPS_SECRET`) are in the persistence generator and its five baselines (`sangam-persistence/tools/generate_changelogs.py`, `sangam-0001-baseline.sql`). The SL-44 tables `OPS_BULK_JOB`, `OPS_BULK_CHUNK`, `OPS_BULK_ROW`, `OPS_BULK_KEY` are in the generator too (changesets 0032-01…04).
- **Bulk ingest settings:** `sangam.ops.bulk.max-rows-per-chunk` (1000), `max-chunk-bytes` (4 MiB), `max-chunks-per-job` (10000), `max-rows-per-job` (1000000), `max-active-jobs-per-tenant` (10), `max-attempts` (5), `worker.batch` (100), `worker.poll-millis` (2000), `worker.stale-millis` (300000). Set `sangam.rest.node` to a distinct id per node so a restart resumes only its own rows at once.
- **Server wiring** (sangam-server `OpsWiring`, `OpsBindings`, `OpsTaskListenerPlugin`; off unless `sangam.modules.ops.enabled=true`):
  - `GlobalTaskListeners` as an engine plugin (`OpsTaskListenerPlugin`), with rules from `sangam.ops.task-listeners-json`.
  - `ScopedVariables` as the engine bean `sangamVars`.
  - `SecretAdmin` with the server's `FieldEncryptor`; its `resolver` is the tenant-scoped bean `sangamTenantSecrets`.
  - `SequenceAdmin` is wired for `RES_BOOKING_SEQ` only. `CFG_SERIES` is not wired.
  - Leader-elected schedules: `UsageMetrics.rollup` (hourly, previous UTC day), `SearchIndexMaintenance.drift` (hourly, logged) and `HierarchyRetention` (daily: plan and log; it purges only with `sangam.ops.retention.auto-execute=true`).
  - `GlobalSearch.engineSources` through the sangam-security policy compiler. Without the security module there are no sources, so search and outlier reads return nothing.
  - `LegacyHistoryMigrator` is wired for the migration status read only. Nothing in the server starts a migration run.
- **REST endpoints:** sangam-rest `OpsUiController` (`/api/v1/search`, `/api/v1/ops/{usage,outliers,variables,secrets,sequences,index-jobs,migration-status,retention/*}`) and `OpsController` (`/api/v1/ops-admin/**`). Each checks the caller's permission (`PermissionPort`) and acts on the caller's tenant.
- **Screens:** `sangam-ui` `src/modules/platform.tsx`: the `/ops/tools` page (usage, outliers, variables, secrets, sequences, index jobs, migration status, retention plan and execute) and the `Ctrl+K` search dialog in the layout. Not built: the bulk ingest screen (SL-44, above).

## Third-party dependencies

`operaton-engine` (Apache-2.0, optional, provided at runtime) and Jackson (Apache-2.0). H2 for tests only.
