# sangam-packs tools: pack generator

`packgen/` generates every pack resource of this module from Python definitions:

- `src/main/resources/packs/<pack>/`: BPMN (with diagram layout), DMN, CMMN, forms, `seed.json`, `pack.json`, and the tenant overrides under `overrides/<tenant>/`;
- `src/main/resources/META-INF/sangam/packs.idx`;
- `README.md` of the module (catalogue and coverage map).

Those files are the committed source that the engine deploys. Do not edit them by hand. Change the generator, regenerate, and commit both.

## Requirements

Python 3.10 or later, standard library only (no packages to install).

## Regenerate

From the `sangam/` directory (any working directory works, because paths are resolved from the script location):

```
python sangam-packs/tools/packgen/main.py            # rewrite resources and README.md
python sangam-packs/tools/packgen/main.py --check    # compare with the repository, exit 1 on any difference
python sangam-packs/tools/packgen/main.py --out DIR  # write to DIR/resources and DIR/README.md instead
```

`--check` generates into a temporary directory and reports, for `packs/` and `META-INF/sangam/`:

- files that differ;
- files the generator produces but the repository lacks;
- **stale** files in the repository that the generator no longer produces.

Normal generation only writes files. It never deletes them, so remove stale files that `--check` reports yourself.

After regenerating, build and run the fast tests (H2, no Docker):

```
mvnw.cmd -q -B -pl sangam-packs -am install
```

| `packs.py` | `Pack` container; writes models, forms, seeds, manifests and `packs.idx` |

| `core.py` | `sangam.core`: the government approval core blocks and core DMN |

| `gov2.py` | IFMS, works / WAMS, work order, tender, consultancy, GeM purchase, security instruments, contract management |
| `gov_ifms.py` | `gov.ifms.*` public-finance packs on the generic services (`config.*`, `ledger.*` connectors): catalogue-driven bill (13 bill-type families), PAO chain, allocation chain, re-appropriation rules, BE / RE, supplementary, surrender and lapse, GIA / UC, SNA-SPARSH, receipts, GPF, loans and advances, monthly accounts, year-end closing, scheme appraisal, audit para settlement; government data is in `src/main/resources/profiles/` (not generated by packgen) |

| `sec_fin.py` | `sec.bank.*`, `sec.nbfc.*`, `sec.cap.*`, `sec.ins.*`, `sec.fin.*` (financial services; SEC-BANK / NBFC / CAP / INS / FIN) |
| `sec_more.py` | gap-closure sector packs (DEA Fund, DLG cap, surveillance, corporate actions, IPO, death claims, reinsurance, intermediaries, OT, blood bank, GST TCS, TCCCPR, SIM swap, e-way bill, MRP, examinations, scholarships, meter-to-cash, disconnection, payroll, appraisal, litigation) |
| `sec_other.py` | `sec.health.*`, `sec.ecom.*`, `sec.tel.*`, `sec.scm.*`, `sec.mfg.*`, `sec.edu.*`, `sec.util.*`, `sec.hr.*`, `sec.legal.*` |
| `sec_ushealth.py` | `sec.ushealth.*` (USA healthcare, US-HLT-nnn in `spike/results/US-HEALTH-WORKFLOWS.md`), English + Spanish |

Second locale other than Hindi: a pack created with `Pack(..., second='es')` writes `{en, es}` labels; its `name_hi` argument and the `|` halves of task names are in that language, and the labels come from `packs.LOCALES['es']` (registered by the pack module). Packs without `second` are unchanged (`{en, hi}`).

Sector packs use ids `sec.<sector>.<slug>` and directories `packs/sec-<sector>-<slug>/`. Government packs (including the IFMS central / state packs another workstream adds) stay under `gov.*`; do not put them in the sector modules.
| `readme.py` | the module README |

## Conventions the generator enforces

- A task name may be `English | Hindi`. The BPMN keeps only the English part; the form carries both.
- Every form field and decision option must exist in `forms.py`, or generation stops with a list of what is missing.
- Element ids are explicit and stable. Keep them stable across versions, so that `PackMigrator` can map running cases (GP-20).
- Output is deterministic: running the generator twice produces identical files.

## Pack configuration example: works order of sanctions

`gov.works` reads the order of sanctions from the DMN `works-config` (output `worksSanctionOrder`):

- `TS_FIRST` is the default: estimate, then technical sanction, then administrative approval.
- `AA_FIRST` swaps the two sanctions.

You can set it in two ways:

- **For one department:** add a row for its office in `works-config` in `gov2.py`. The sample row is office `DIV-WK-AAFIRST`.
- **For a whole tenant:** add a `pk.override('<tenant>', 'works-config', ...)` entry. The sample is `state-b`, which uses `AA_FIRST`. Deploy that tenant with `PackDeployer.deploy(List.of("gov.works"), "<tenant>")`, which also deploys the dependencies for that tenant.
