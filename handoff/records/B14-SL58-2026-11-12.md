# B14 — SL-58 investigation (2026-11-12)

**Verdict: (c) an IFMS-side harness defect (IFMS P-429). It is not a Sangam defect and needs no Sangam code.** Confidence: **98%**.

The failure is not specific to SQL Server 2025 or JDK 25. The arithmetic in the shared conformance kit's T-4 scenario never moves the harness clock past the timers' due instant at SMOKE scale (4 timers, 2 restarts). The timers therefore never come due, on any engine and any database. At ACCEPTANCE scale (500 timers, 10 restarts) the same arithmetic does reach the due instant, so T-4 passes there.

## 2. Root cause, traced in the harness at `3834d4c`

The T-4 scenario is in `tests/workflow-conformance/src/main/java/in/oneifms/workflow/conformance/ConformanceKit.java`, `t4`, l.453–499:

```java
Instant last = due.values().stream().max(...)...;
Duration step = Duration.between(a.clock().now(), last).dividedBy(scale.restarts() + 1);   // l.472
for (int k = 0; k < scale.restarts(); k++) { a.clock().advance(step); a.restart(); }      // only restarts steps, not restarts+1
a.clock().advance(Duration.ofDays(1));                                                     // fixed 1 day closes the last step
```

The scenario advances the clock by `restarts` steps of `gap/(restarts+1)` each, then by a fixed 1 day. The last due instant is reached only if `gap/(restarts+1) <= 1 day`.

**Concrete numbers, which match the log to the minute:**
1. T-3 (l.385–440) leaves the clock at `expected − 60 s − 1 s + 121 s + 1 d`. With `expected = 2026-11-18T05:30Z` (log l.2928) and `TOLERANCE = 60 s` (l.59), T-4 therefore creates its timers at **2026-11-19T05:31Z**.
2. SLA2WD gives a due instant of **2026-11-24T05:31Z** (log l.2929), so the gap is exactly **5 days**.
3. **SMOKE (restarts 2; `Scale.java:24`):** each step is 5 d / 3 = 40 h. After 2 steps and the final day, the clock stands at 05:31 + 104 h = **2026-11-23T13:31Z**, which is before the due instant. The timer never comes due, which gives `firedAt=null, fireCount=0` for all 4 timers. That is exactly the symptom.
4. **ACCEPTANCE (restarts 10; `Scale.java:22`):** each step is 5 d / 11 ≈ 10.9 h. The clock ends at about **2026-11-24T18:36Z**, after the due instant. `EngineClock.advance` stops the clock at the due instant and drains the job (see below), so the timer fires exactly once at its stored instant: 500/500 PASS.

The engine side behaves correctly:
- `trials/workflow-sangam/.../EngineClock.java` `advance`/`nextDue`/`drain` walks to each due job at or before the target, and only those.
- No job lies before the target at SMOKE, so the job executor is never asked to run anything.
- Sangam code is never on the decision path. The result does not depend on the database, the driver or the JDK.

**The defect is still unfixed in IFMS.** Every oneifms branch that carries the kit still has the l.472 arithmetic and the 1-day closer, among them `wf/trial2-sangam`, `cc/wp04-*`, `cc/p466-trial2-adapter`, `cc/ci-fixes-2026-11-12` and `integ/test-phase-2026-11-09`.

## 4. What closes SL-58

- **Sangam:** no code. Close as "not a Sangam defect — IFMS P-429 harness arithmetic", with this report as evidence.
- **IFMS (owner of P-429, for the ledger).** Proposed generic fix in `ConformanceKit.t4`:
  - either close the last segment with `advance(Duration.between(now, last).plus(TOLERANCE.multipliedBy(2)))`, then the existing 1-day margin;
  - or advance `restarts + 1` steps, restarting after the first `restarts`.
- **Proving test (IFMS, lock-free).** Run the kit's stub adapter (`stub/IncompleteStubAdapter`) or an in-memory timer adapter at SMOKE with `gap/(restarts+1) > 1 day`. It must report `firedExactlyOnce == timers`; the current code reports 0. This also satisfies E-53 S-D-429, "T-4 at SMOKE scale must pass".
- **Optional run to confirm, only if wanted:** after the IFMS fix, rerun `SangamMsSqlConformanceIT -Dit.trial.scale=SMOKE -Dit.test=SangamMsSqlConformanceIT` on SQL Server 2025 CU10 / JDK 25 under the heavy lock. The expected result is T-4 PASS 4/4. It is not needed to decide SL-58, because the deciding ACCEPTANCE control already exists (`24644b2`).
