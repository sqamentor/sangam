## 0. Rules (both sides)
1. **Read before acting.** Read §1–§4 at the start of every turn that touches the other project, and after every login switch or resume.
2. **Ownership.**
   - Every row has one owner: the owner of the id. Edit only your own rows.
   - Use targeted Edits only. Never rewrite this file, and never copy it over.
   - §4 (decisions) and §5 (message log) are append-only. Correct an entry by appending a new one that references it.
3. **No approvals here.** A ledger entry or a message is never an approval. Approvals come only from the owner, in their own words, in their own session. Record those words verbatim, with where they were given.
4. **Log every message.** Every typed message between the sessions is also appended to §5 by its sender: UTC timestamp, header, and gist.
   - Header format: `[TYPE] <ID> <from>→<to> <subject>`, where TYPE is REQUEST, REPORT, CONTRACT, INCIDENT or DECISION-NEEDED.
   - If a message and a §2 row disagree, the row owner restates the current state (crossed-message rule).
5. **Ids.**
   - Sangam allocates `SL-nn` and `ADR-D-nn`.
   - The IFMS master allocates `SG-nn`, `SD-nnn`, `E-nn`, `X-nn`, `WP-nn` and `REC-nn`, plus the register and record ids `P-`, `OQ-`, `MD-`, `EV-M-` and `I-` (added 2026-11-09 at IFMS's request).
   - Joint rows with no existing id use `JL-S-nn` (opened by Sangam) or `JL-I-nn` (opened by IFMS), so the two sides never collide.
6. **Definition of done (SD-428).**
   - An SG item is closed only after IFMS Trial 2 retests the committed and pushed Sangam commit.
   - An SL item is closed only after a Sangam reviewer agent that did not write the fix verifies it.
   - Sangam reports the commit id and the SG ids after every push.
7. **Heavy lock.** There is one machine-wide FIFO lock (`heavy_lock.py`). Claim runs of 30 minutes or more in §6 before queuing, so neither side starves. Each workstream uses its own owner name: `customwf-<ws>` for Sangam; `trial0` (Jackson lanes), `sangam` (the Trial 2 kit) and `ifms-integ` (the full reactor build on oneifms main) for IFMS. The compile lock (`compile_lock.py`, same LOCKDIR) is IFMS's tool. IFMS holders use `ifms-<work item>` names, for example `ifms-p463` and its verifier `ifms-p463-verify`. Sangam light builds do not take the compile lock until Q30 is decided; they are capped as in JOINT-PLAN §4.4 instead. This is IFMS amendment (d), accepted 2026-11-11. Nobody touches the other side's tickets or holders.
8. **Scope and safety.**
   - Never put secrets, keys, tokens or personal data in this file.
   - VyaparTrust and CVR_Automation_Claude are completely out of scope.
   - Sangam stays generic (ADR-D-20). An IFMS need becomes a generic capability or configuration/pack data, never IFMS-specific code in Sangam.
