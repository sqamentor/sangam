## Part 2: conflicts and tensions

Each entry gives the clash and the option that resolves it. Items marked *tension* do not contradict a recorded decision outright, but they need the owner's explicit choice.

1. **W4Q-09 (M-108) versus D8 and spec R17.**
   - Clash: marking CockroachDB "unsupported" removes a known 0.1.0 item. `SANGAM.md:600` and `SANGAM.md:1674` (R17) name CockroachDB and YugabyteDB as the experimental tier, and BL:224 scopes both. The licence-change reason is UNVERIFIED.
   - Resolve, either:
     - keep CockroachDB in 0.1.0 as experimental and NOT-RUN, with the engine-mapping gap documented, plus a dialect file and a non-gating CI lane that reports NOT-RUN, never PASS (D137(5)); or
     - have the owner record an explicit exception to D8 that amends R17.
2. **W4Q-17 (Camel) versus D137(2).**
   - Clash: the recommendation asks for D-4 and an optional module now. D137(2) defers D-4 "unless an approved integration needs it now", and no approved integration names Camel (GraphQL, S3 and JDBC landed without it, SB:119).
   - Resolve: take the alternative "drop Camel from 0.1.0", recorded as a D8 exception, with the ConnectorRegistry SPI as the extension point for a later optional module. Any later Camel module must route every endpoint through `HttpTransport`/EgressPolicy.
3. **W4Q-24 (M-135) versus D8.**
   - Clash: the whole item is deferred, but only the real corpus is external input.
   - Resolve: in 0.1.0, code the R48 pipeline (inventory, dry-run, rejection of unsupported states, freeze/drain, mapping, reconciliation, duplicate-effect protection) against synthetic fixtures. Validation on the real corpus becomes a test-phase input. If even that is unwanted, the owner records an explicit D8 exception. It also depends on FC-18, see item 5.
4. **W4Q-25 (M-129 native indexes) versus D8 and the M-129 scope.**
   - Clash: BL:260 scopes "pgvector on PG; native vector types where the Tier-1 DB has one".
   - Resolve, either:
     - in 0.1.0, add pgvector (PG) and Oracle VECTOR behind the existing `VectorIndex` port, as optional, with the portable index staying the default and an equivalence test; or
     - have the owner record an explicit exception.
   - No correctness impact: the portable index is exact.
5. **W4Q-23 (M-107) versus D8.**
   - Clash: the cited evidence "PATCHES.md already says on proven demand only" holds for P-4 only (`sangam-flowable-ports/PATCHES.md:28`) and for native FC-19 (`FLOWABLE-INTO-OPERATON.md:130`). It does not hold for:
     - FC-18 historic-instance migration: medium feasibility, stage D (`FLOWABLE-INTO-OPERATON.md:129`), and M-135 needs it;
     - EC-06 REST-backed data objects: still 501 (`JdbcLowCodeAdapter.java:38`) and not mentioned in the recommendation at all.
   - Resolve: accept the gap for P-4 and native P-5/FC-19 only. Keep FC-18 and EC-06 in 0.1.0 (EC-06 over the R71 connector layer that exists now).
6. **W4Q-02 and W4Q-03 (engine items left to the test phase): tension with D8 and the correctness-first order.**
