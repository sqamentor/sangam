# Sector workflows and regulatory controls (SECTORS workstream)

Status: 2026-11-04. Scope: the standard workflows of non-government sectors that Sangam must run end to end, and the regulatory controls each one enforces. Requirements are numbered **SEC-&lt;SECTOR&gt;-nnn**. Each workflow is mapped to the packs in `sangam/sangam-packs` and marked **covered**, **partial** or **missing** (state before this workstream → state after).

Implementation: 54 sector packs (`sec.*`: 66 BPMN processes, 70 DMN tables, 208 bilingual forms) generated by `sangam-packs/tools/packgen` (`sector.py`, `sector_forms.py`, `sec_fin.py`, `sec_other.py`, `sec_more.py`). The first pass added 32 packs; the gap-closure pass (section 15) added 22. Section 16 is the verify-before-go-live register. Every pack reuses the approval core: scrutiny, sanction with SoD, power and payload binding, execution with operationId and UNKNOWN_OUTCOME, closure, rejection and appeal, and the cancellation side exits. External systems are reached only through `ConnectorGateway`. Large sets use one instance per item (GP-09); no multi-instance is used.

How to read the timelines:
- **Primary**: confirmed on the regulator's own site.
- **Secondary**: confirmed only in reputable secondary reporting; marked *(verify)*. Those values sit in DMN tables, so a tenant override changes them without touching the models (GP-37).

Several Indian rules changed in 2025–2026: RB-IOS 2026, the RBI E-mandate Framework 2026, RBI technology Master Directions of 31 July 2026, and the DPDP Rules 2025 being phased in. Re-check the current text before go-live.
